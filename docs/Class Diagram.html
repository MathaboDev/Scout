Scout documentation

Class Diagram

Django models that back Scout's API. Every Scout model declares managed = False because the schema lives in database/schema.sql; Django only owns its own auth tables. Views consume these models through serializers.

Notes

  • User is Django's auth.User. is_staff=True plus a matching PlatformAdmin row by email is the signal that identifies an administrator.
  • PlatformAdmin is deliberately named to avoid collision with django.contrib.admin.
  • DRF permission classes attach the resolved role row to the request (request.student, request.provider, request.admin) so views never re-query.
  • The student.password_hash legacy column is nullable and unused; Django's auth_user.password is the real credential store.
